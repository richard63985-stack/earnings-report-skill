# 财报点评与配套底稿

先识别本次是写正文、给已有Word配底稿、同步返修，还是模板刷新。读取项目规则和用户认可样稿，确认允许修改的范围。当前用户授权优先于Skill的默认步骤；已明确的事项不重复询问。

## 执行入口

1. 从项目识别公司、财报期、来源、模板及评级口径。区分模板的固定栏、授权填写区与用户明确要求的刷新区；没有正式模板才用中性演示模板，不伪造机构署名。
2. 需要运行脚本时读 [运行与脚本](references/runtime.md)，先复用环境，仅补实际缺项。业务材料与生成过程放项目目录，Skill目录只放通用方法和工具。
3. 写正文时读 [写作规则](references/writing.md)，使用官方公告/SEC/IR等一手资料，按 [来源与配置](references/evidence.md) 同步记录逐句证据。
4. 生成或修改Word后按 [验收清单](references/quality.md) 检查模板与全部页面。仅请求Word不自动继续底稿。默认取得用户对准确版本的确认；用户明确授权主控复核后连续制作时，按授权范围完成复核即可继续，不逐篇追加确认。
5. 用 `freeze_word.py` 锁定准确Word的哈希与正文。读取 [底稿规范](references/workpaper.md)，按锁定正文整理四表点位，集中列输入、公式、结果及组内来源编号。真实用户确认与受委托复核分别记录，不能相互冒充。
6. `create_visual_workpaper.py --validate-only` 后生成Excel，检查实际单元格、嵌入图片、译文与对应渲染。结构通过不证明事实或截图支持结论。
7. 返修另存Word/Excel和过程目录，更新对应映射、核验说明及图片。模板刷新导致Word哈希变化时也要重新建立版本关联；是否再次询问用户取决于已有授权，不以文件哈希变化机械新增审批。
8. 批量、独立审阅或迁移时，读 [批量审阅与交接](references/batch-handoff.md)。上传只按用户指定目标及实际授权执行，制作通过不等于上传成功或正式发布。

## 必须保持

- 最终Word是底稿正文准绳；缺证据时补来源或按授权返修正文，不为截图方便偷偷改句。
- 尊重已确认研究主线，事实、公司指引、计算及判断分清；不编造利好，也不把特定项目的投资立场或推荐评级固化成全局默认。
- 正文交付研究结论，核验提醒、计算过程和制作说明放底稿对应区域。模板固定栏默认保留，脚本不能自行改成“审阅稿”等新标签。
- 核对数据、原始截图、忠实中文译文各有位置；跨期数值及公式同组相邻。默认四张正文表，无自动盈利预测表或来源索引表。
- 报告“已生成、内部复核通过、用户确认、上传成功”各自真实范围；原生Office与跨平台未验证项如实保留。
