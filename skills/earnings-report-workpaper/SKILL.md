# 财报点评与配套底稿

先识别用户要写正文、制作底稿，还是两者一起做。遵循用户项目的现行风格与模板；无项目规则时采用本 Skill 的默认写法。不要把此流程扩大为通用深度报告、自动评级或无人审核的发布系统。

## 执行入口

1. 确认公司、财报期、材料、报告模板、输出目录及用户已有评级观点。可从已有项目文件识别，无须重复询问。缺少正式模板时用随附脚本生成中性草稿模板；不得伪造券商署名、评级或免责声明。
2. 首次运行阅读 [运行与脚本](references/runtime.md)，安装 requirements 并检查中文字体和浏览器。所有业务材料保留在用户项目，不能写入 Skill 安装目录。
3. 写作读取 [写作规则](references/writing.md)，先搜官方财报公告/SEC/IR，再电话会与演示材料；按 [来源与配置](references/evidence.md) 同步维护句子来源草稿。
4. 使用 `fill_report_template.py` 生成 Word；模板必须具有文档说明的内容控件。读取 [验收清单](references/quality.md)，渲染检查后请用户确认 Word。仅请求制作 Word 不自动继续底稿。
5. 用户已确认 Word 后，用 `freeze_word.py` 记录其哈希与段落。读取 [底稿规范](references/workpaper.md)，按最终 Word 重排句子来源，补齐新增句的证据并制作配置。`word_confirmed` 只能记录真实确认，不能由脚本自行代替人判断。
6. `create_visual_workpaper.py --validate-only` 后正式生成 Excel，核验所有 sheet 与关键截图。脚本只能核对路径、正文与引用结构，不能证明来源支持结论。没有证据的句子需补来源或回到正文修改、重新确认，不能通过关闭校验掩盖缺口。
7. 返修同时维护 Markdown、来源映射、Word、配置和 Excel。以新文件版本输出；Word 有变化时旧哈希失效，重新获取确认。只有用户明确要求才同步提交件或上传外部系统。

## 不变规则

- 不凭空补数据、出处、公司表述、评级、盈利预测或计算结果。
- 写作时就记录来源，Word 确认前不提前制作正式截图底稿。
- 最终 Word 是底稿正文唯一准绳；不为方便找证据而反向改 Word。
- 每个核心数字保留期间、币种、单位、GAAP/Non-GAAP 等口径；计算保留输入与公式，归纳判断与公司前瞻表述分开标记。
- 默认四个正文 sheet、逐句左右对照、黄色分隔。CSV/JSON 为过程记录，不另塞来源目录或索引 sheet。
- 不把旧批次的推荐评级、机构模板或私人目录固化成通用默认值。
